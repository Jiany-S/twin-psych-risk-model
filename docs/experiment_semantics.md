# Experiment Semantics

This document freezes the current experiment meanings as of 2026-07-21. It is descriptive, not a recommendation that the current semantics are scientifically valid.

## Target Definitions

| Dataset | `y_stress` currently means | `y_comfort_proxy` currently means | Valid wording |
| --- | --- | --- | --- |
| Synthetic | Synthetic binary risk/stress label generated by `src/data/synthetic.py`. | Synthetic inverse/comfort proxy. | Synthetic risk. |
| WESAD | Protocol label 2 (`stress`) is positive. Protocol label 1 (`baseline`) is negative. Protocol label 3 (`amusement`) is negative when `stress_include_amusement: true`; otherwise excluded. | Fixed protocol score: baseline 0.9, stress 0.2, amusement 0.7. | Stress-vs-baseline/amusement protocol classification. |
| MultiPhysio | Normalized `STAI` state-anxiety score. The immediate benchmark primary target is `y_cognitive_load_binary`, not `y_stress`. | SAM Valence normalized from 1..5 to 0..1. | STAI state anxiety for stress; NASA-TLX for cognitive workload; SAM Valence for comfort proxy. |

NASA-TLX should not be presented as a direct stress label. It can be discussed as workload or a workload/stress proxy only with clear caveats.

| Dataset | Target | Source | Interpretation |
| --- | --- | --- | --- |
| WESAD | stress | protocol label | experimentally induced stress |
| MultiPhysio | stress | STAI-Y1 (`STAI`) | self-reported state anxiety |
| MultiPhysio | cognitive load | NASA-TLX (`NASA`) | perceived workload |
| MultiPhysio | comfort proxy | SAM Valence (`Valence`) | affective valence |
| MultiPhysio | arousal | SAM Arousal (`Arousal`) | affective activation |

## Channel Semantics

| Dataset | `ecg` | `eda` | `temp` | Optional |
| --- | --- | --- | --- | --- |
| Synthetic | Synthetic ECG-like signal. | Synthetic EDA-like signal. | Synthetic temperature-like signal. | Robot context if enabled. |
| WESAD | Chest ECG, with wrist BVP fallback only if chest ECG missing. | Chest EDA, with wrist EDA fallback only if missing. | Chest Temp, with wrist TEMP fallback only if missing. | Chest Resp and ACC when present. |
| MultiPhysio | `hrv_mean_nn` from `HRV_MeanNN`, already a 60-second HRV feature, not raw ECG. | `eda_mean` from `EDA_mean`, already a 60-second EDA feature. | No temperature column is created unless a real temperature source is configured. | `emg_rmse` from `EMG_RMSE`; `rrv_mean_bb` from `RRV_MeanBB`. |

For MultiPhysio, the current physiology columns are precomputed 60-second features. They are not raw ECG/EDA/temperature samples, and precomputed HRV values do not go through raw ECG peak detection.

Current window label rule in `build_windows`: durations are converted to row counts centrally, and for a window `[start, end)`, the label is taken from `end + horizon_steps - 1`. The label timestamp must equal the final observation timestamp plus `forecast_horizon_seconds`.

## Profile Behavior

Prompt 4 update: the old mixed profile behavior below has been superseded in code. Personalization now separates train-fitted global normalization, explicit baseline/rest calibration normalization, and optional profile-vector inputs. `worker_id` is now only a TFT grouping identifier, not a static categorical covariate, and validation/test worker IDs are no longer inserted into the TFT training frame. Missing real role metadata is `-1`; missing real experience metadata is `0`; hash-generated role/experience metadata has been removed.

The current profile input flags are:

| Flag | Meaning |
| --- | --- |
| `normalization.mode: global` | Fit physiology normalization statistics on training rows only and apply to validation/test. |
| `normalization.mode: calibration` | Normalize each subject by explicit unlabeled baseline/rest calibration rows. |
| `profiles.include_calibration_features` | Append calibration mean/std/median/robust-scale values to model inputs. |
| `profiles.include_role_metadata` | Append real role metadata only when a dataset provides it; otherwise keep disabled. |
| `profiles.include_experience_metadata` | Append real experience metadata only when a dataset provides it. |

| Current setting | XGBoost current behavior | TFT current behavior | Caveat |
| --- | --- | --- | --- |
| Profile flags all false | No appended profile columns; physiology is normalized according to `normalization.mode`. | No profile static real covariates; `worker_id` is grouping only. | This isolates normalization from profile-vector inputs. |
| `include_calibration_features: true` | Appends calibration statistics to the engineered feature matrix. | Passes calibration statistics as static real covariates. | Calibration statistics must come only from explicit baseline/rest rows. |
| `include_experience_metadata: true` | Appends real experience metadata where available. | Passes experience metadata as a static real covariate. | Keep disabled for datasets without real experience metadata. |
| `include_role_metadata: true` | Appends real role metadata where available. | Passes role metadata as a static real covariate. | Keep disabled for WESAD and current MultiPhysio because no real role field is loaded. |

## Split Semantics

| Split mode | Current implementation | Scientific interpretation |
| --- | --- | --- |
| Time split | Chronological split within each worker. `run_experiment.py` asserts train < val < test per worker. | Tests future rows for seen workers. Subject identity memorization is expected and not a subject-generalization claim. |
| Subject holdout | Disjoint worker IDs in raw train/val/test. `run_experiment.py` asserts no overlap. | XGBoost is closer to valid subject generalization. TFT is not clean because it uses held-out `worker_id` categories and artificial rows. |

## Model Input Comparability

| Aspect | XGBoost | TFT | Comparable today? |
| --- | --- | --- | --- |
| Window construction | Explicit NumPy windows with `window_step`. | `TimeSeriesDataSet` encoder/prediction windows; for `window_step > 1`, rows are first strided. | Not exactly. |
| Engineered features | Raw WESAD/synthetic runs use HRV/EDA/temp signal features. MultiPhysio runs use aggregate features over precomputed columns such as `hrv_mean_nn`, `eda_mean`, `emg_rmse`, and `rrv_mean_bb`. | Raw or precomputed row-level reals plus known covariates, depending on config. | No; model families intentionally differ, but row semantics must be clear. |
| Profiles | Optional calibration and real metadata profile columns appended when enabled. | Same enabled profile columns are passed as static real covariates. | Closer, but XGBoost still uses engineered windows while TFT uses row-level sequence covariates. |
| Subject IDs | Not appended as features. | Used only as `group_ids` for sequence construction. | Cleaner for holdout; still verify prevalence and grouping behavior per run. |

## Metrics Semantics

| Metric | Current code | Interpretation risk |
| --- | --- | --- |
| AUROC | `roc_auc_score`, NaN for single-class test. | Less prevalence-sensitive than F1/AUPRC, but can be unstable with tiny splits. |
| AUPRC | `average_precision_score`. | Baseline is test prevalence; must be reported alongside prevalence. |
| F1/precision/recall | Uses threshold selected on validation by configured policy, default F1. | Strongly prevalence- and threshold-policy-sensitive. Do not compare across shifted class balance as model improvement. |
| Brier/ECE | Computed on predicted probabilities. | Calibration changes are prevalence-sensitive and can be distorted by isotonic calibration on small validation sets. |

The tracked `docs/weekly_reports/2026-04-16.md` correctly notes that a MultiPhysio split change shifted test prevalence substantially. Those metric gains should be treated as split-validity improvement, not a final benchmark.
