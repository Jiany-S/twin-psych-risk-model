# Experiment Semantics

This document freezes the current experiment meanings as of 2026-07-20. It is descriptive, not a recommendation that the current semantics are scientifically valid.

## Target Definitions

| Dataset | `y_stress` currently means | `y_comfort_proxy` currently means | Valid wording |
| --- | --- | --- | --- |
| Synthetic | Synthetic binary risk/stress label generated by `src/data/synthetic.py`. | Synthetic inverse/comfort proxy. | Synthetic risk. |
| WESAD | Protocol label 2 (`stress`) is positive. Protocol label 1 (`baseline`) is negative. Protocol label 3 (`amusement`) is negative when `stress_include_amusement: true`; otherwise excluded. | Fixed protocol score: baseline 0.9, stress 0.2, amusement 0.7. | Stress-vs-baseline/amusement protocol classification. |
| MultiPhysio | `labels.csv` NASA-TLX score thresholded at `>= 40.0` by default. | SAM Valence normalized from 1..5 to 0..1. | High NASA-TLX workload classification; Valence regression proxy. |

NASA-TLX should not be presented as a direct stress label. It can be discussed as workload or a workload/stress proxy only with clear caveats.

## Channel Semantics

| Dataset | `ecg` | `eda` | `temp` | Optional |
| --- | --- | --- | --- | --- |
| Synthetic | Synthetic ECG-like signal. | Synthetic EDA-like signal. | Synthetic temperature-like signal. | Robot context if enabled. |
| WESAD | Chest ECG, with wrist BVP fallback only if chest ECG missing. | Chest EDA, with wrist EDA fallback only if missing. | Chest Temp, with wrist TEMP fallback only if missing. | Chest Resp and ACC when present. |
| MultiPhysio | `HRV_MeanNN` by default, already a 60-second HRV feature, not raw ECG. | `EDA_mean` by default, already a 60-second EDA feature. | `EMG_RMSE` by default, not temperature. | `RRV_MeanBB` as respiration feature. |

For MultiPhysio, the current `ecg`, `eda`, and `temp` names are compatibility aliases. They are not raw ECG/EDA/temperature samples.

Current window label rule in `build_windows`: for a window `[start, end)`, the label is taken from `end + horizon_steps - 1`. Therefore `horizon_steps: 1` predicts the first row after the encoder window.

## Profile Behavior

| Setting | XGBoost current behavior | TFT current behavior | Caveat |
| --- | --- | --- | --- |
| `profiles.enabled: true`, `use_static_meta: true` | Adds static profile table columns to engineered features. Physiology is normalized according to normalization/profile mode. | Adds baseline mean/sigma as known reals and includes `worker_id`, `specialization_index`, `experience_level` as static categoricals. | Static categorical `worker_id` is unsafe for subject holdout. |
| `profiles.enabled: true`, `use_static_meta: false` | Usually no appended profile columns; input still affected by normalization. | Adds baseline mean/sigma known reals because `use_profiles=True`. | XGB and TFT do not receive equivalent profile information. |
| `profiles.enabled: false` with `normalization.mode: online` | No static profile table, but physiology is still online-normalized and baseline columns exist in flat frames. | No profile known reals, but physiology is still online-normalized. | "Profiles off" is not necessarily "raw signals." |
| Built-in XGB ablation in `run_experiment.py` | Reuses the already-engineered `X_all`; only removes appended static profile table. | No built-in TFT ablation. | If static profiles are empty, profiles-on/off XGB ablation can be identical. |

## Split Semantics

| Split mode | Current implementation | Scientific interpretation |
| --- | --- | --- |
| Time split | Chronological split within each worker. `run_experiment.py` asserts train < val < test per worker. | Tests future rows for seen workers. Subject identity memorization is expected and not a subject-generalization claim. |
| Subject holdout | Disjoint worker IDs in raw train/val/test. `run_experiment.py` asserts no overlap. | XGBoost is closer to valid subject generalization. TFT is not clean because it uses held-out `worker_id` categories and artificial rows. |

## Model Input Comparability

| Aspect | XGBoost | TFT | Comparable today? |
| --- | --- | --- | --- |
| Window construction | Explicit NumPy windows with `window_step`. | `TimeSeriesDataSet` encoder/prediction windows; for `window_step > 1`, rows are first strided. | Not exactly. |
| Engineered features | HRV/EDA/temp summary features from the model window. | Raw or aliased row-level reals plus known covariates. | No; model families intentionally differ, but row semantics must be clear. |
| Profiles | Static profile table appended only in some configs. | Baseline known reals when `use_profiles=True`; static categoricals always include worker/meta. | No. |
| Subject IDs | Not appended unless static profile table indirectly includes subject-derived hash/meta. | Always included as static categorical. | No, especially under holdout. |

## Metrics Semantics

| Metric | Current code | Interpretation risk |
| --- | --- | --- |
| AUROC | `roc_auc_score`, NaN for single-class test. | Less prevalence-sensitive than F1/AUPRC, but can be unstable with tiny splits. |
| AUPRC | `average_precision_score`. | Baseline is test prevalence; must be reported alongside prevalence. |
| F1/precision/recall | Uses threshold selected on validation by configured policy, default F1. | Strongly prevalence- and threshold-policy-sensitive. Do not compare across shifted class balance as model improvement. |
| Brier/ECE | Computed on predicted probabilities. | Calibration changes are prevalence-sensitive and can be distorted by isotonic calibration on small validation sets. |

The tracked `docs/weekly_reports/2026-04-16.md` correctly notes that a MultiPhysio split change shifted test prevalence substantially. Those metric gains should be treated as split-validity improvement, not a final benchmark.

## Blockers Before Next Phase

1. Decide whether MultiPhysio experiments are workload forecasting, stress-proxy forecasting, or should use a different label.
2. Decide how to represent MultiPhysio EMG without pretending it is temperature.
3. Define a single source of truth for sampling rate after loader operations.
4. Remove TFT subject ID leakage before claiming subject-holdout generalization.
5. Add prevalence and dummy baselines to every stress result before interpreting F1/AUPRC.
